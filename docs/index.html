C++Extended (cxxe)

C++ is powerful, but it carries decades of ceremony: plumbing to observe a variable, boilerplate for getters, fragile macros for converting an enum to a string, and misused destructors to imitate finally.

C++Extended (compiler: cxxe) is a C++ superset that keeps 100% of C++ features and adds a layer of modern ergonomics: decorators, signals, defer, native properties, runtime reflection, and more. The principle is simple: cxxe transforms your extended code into standard C++, without removing anything from the original language.

There is no new language to learn. You simply extend the one you already know.

C++ Compatibility

C++Extended is a superset of C++: any valid C++ code is also valid C++Extended code. An existing project can therefore be migrated file by file.

Named Parameters

Arguments can be passed by name, in any order.

int add(int a, int b);

int main() {
    int r = add(b=5, a=4);
}

Native Decorators and Reflection

Native decorators allow classes to be registered and members to be exposed so they can be accessed at runtime by name.

DecoratorRole
@registerRegisters the class in the factory.
@exposedExposes a member to reflection. It must be public.
@register
class A {
public:
    @exposed int health;
};

Creating Instances

// Instantiate by name
A* obj = stde::factory_new("A");
// transformed by cxxe into: new A()

// Get the type by name
A* obj2 = new stde::factory_find("A")();
// transformed by cxxe into: new A()

Accessing Exposed Members

obj->get_member("health") = 4;
// transformed by cxxe into: obj->health = 4;

Dynamic Usage

Everything is resolved at runtime: the name can come from a source unknown at compile time.

stde::factory_new(unknown_string);
An @exposed member must be public.

Custom decorators

You can declare your own decorators. A decorator receives the decorated function (func) and wraps it as you wish.

void @my_decorator() -> func(int a) {
    before();
    func(a);
    after();
}

A decorator can also take parameters:

void @my_decorator(/* decorator parameters */) -> func(int a) {
    before();
    func(a);
    after();
}

Usage:

@my_decorator
void work(int a) { /* ... */ }
Support for templates on decorators is available.

Lifecycle Decorators

Three standard decorators document the evolution of your API.

DecoratorDescription
@deprecated(msg)Marks an element as deprecated, with a message.
@since(version)Indicates the version in which the element was introduced.
@experimental(msg)Marks an unstable API that may change.
@since("1.2")
@deprecated("Use load_v2() instead")
void load();

@experimental("The interface may change")
void new_feature();

Signals — Abandoned

A signal detects changes to a variable and executes a block of code whenever it changes. It works everywhere: global scope, classes, structures, etc.

int my_int = 0;

signal: my_int {
    var_changed();
}

Inside a class:

class Player {
public:
    int score = 0;

    signal: score {
        update_ui();
    }
};

defer

defer executes a block when leaving the current scope, regardless of the exit path.

void process() {
    FILE* f = fopen("data.txt", "r");
    defer { fclose(f); }

    // ... use f ...
}   // fclose(f) is called here

Inspectable Enums

Enums are introspectable: enum → string conversion, string → enum conversion, and other reflection operations.

enum class Color { Red, Green, Blue };

Reflection functions notably include:

  • enum → string conversion;
  • string → enum conversion;
  • other reflection utilities for enum values.

Properties (Native Getters/Setters)

Classes and structures natively support properties with get and set, without boilerplate.

class Character {
    int health;

public:
    property Health {
        get { return health; }
        set { health = clamp(value, 0, 100); }
    }
};

Usage:

Character c;
c.Health = 150;    // calls the setter: health = 100
int h = c.Health;  // calls the getter

Output Redirection (IOutput)

All output can be redirected natively, regardless of the mechanism used in the code:

  • std::cout
  • printf
  • std::print
  • and other standard output mechanisms

Redirection is based on the IOutput interface: implement it to send output to a file, an editor console, the network, a log, etc.

CMake Toolchain

C++Extended integrates with CMake through a dedicated toolchain. Extended sources are processed by cxxe before the usual C++ compilation, so the language can be adopted in an existing project without changing the build system.

Features in Testing & Roadmap

These features are currently in the testing phase. Their syntax and behavior may still change based on testing and feedback.

Type dynamic (Testing Phase)

A type whose actual type is only known at runtime. A dynamic value can hold values of different types and provides is<T>() for type checking and as<T>() for accessing the stored value.

dynamic value = 42;

if (value.is<int>()) {
    int x = value.as<int>();
    std::cout << "int = " << x << std::endl;
}

value = 3.14f;
std::cout << value.as<float>() << std::endl;

value = std::string("hello");
std::cout << value.as<std::string>().c_str() << std::endl;

dynamic can also be used inside standard containers:

std::vector<dynamic> values = { 42, 3.14f, "hello", true };

for (const auto& value : values) {
    if (value.is<int>())
        std::cout << "int: " << value.as<int>() << std::endl;
    else if (value.is<float>())
        std::cout << "float: " << value.as<float>() << std::endl;
    else if (value.is<const char*>())
        std::cout << "string: " << value.as<const char*>() << std::endl;
    else if (value.is<bool>())
        std::cout << "bool: " << value.as<bool>() << std::endl;
}
Calling as<T>() with a type that does not match the stored value results in a runtime error.

Pattern matching (Testing Phase)

A match statement handles a dynamic value according to its runtime type. Inside each branch, value is already treated as the corresponding type.

void Show(dynamic value)
{
    match value
    {
        int:
            std::cout << "Integer: " << value << std::endl;

        float:
            std::cout << "Float: " << value << std::endl;

        const char*:
            std::cout << "String: " << value << std::endl;

        default:
            std::cout << "Unknown type" << std::endl;
    }
}

int main()
{
    std::vector<dynamic> values = { 42, 3.14f, "hello" };

    for (const auto& value : values)
        Show(value);

    return 0;
}

JSON, XML, and Other Data Formats

Native facilities for manipulating common data formats (JSON, XML, etc.) directly from the language.

Automatic Serialization

The @serializable decorator will automatically generate serialization and deserialization for a class.

@serializable
class Config {
public:
    int width;
    int height;
};

Notes and Limitations

  • The examples in this documentation illustrate the syntax; the exact names of functions in the stde library may vary between versions.
  • An @exposed member must be public.
  • Features marked as “Concept” are not implemented yet.
