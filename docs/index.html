C++Extended (cxxe)

Le C++ est puissant, mais il traîne des décennies de cérémonie : de la plomberie pour observer une variable, du boilerplate pour les getters, des macros fragiles pour convertir un enum en chaîne, des destructeurs détournés pour imiter finally.

C++Extended (compilateur : cxxe) est un sur-ensemble du C++ qui garde 100 % des fonctionnalités du C++ et ajoute une couche d'ergonomie moderne : décorateurs, signals, defer, properties natives, réflexion à l'exécution, etc. Le principe est simple : cxxe transforme votre code étendu en C++ standard, sans rien retirer au langage d'origine.

Il n'y a pas de nouveau langage à apprendre. Vous étendez celui que vous connaissez déjà.

Compatibilité C++

C++Extended est un sur-ensemble du C++ : tout code C++ valide est un code C++Extended valide. Un projet existant peut donc être migré fichier par fichier.

Paramètres nommés

Les arguments peuvent être passés par nom, dans n'importe quel ordre.

int add(int a, int b);

int main() {
    int r = add(b=5, a=4);
}

Décorateurs natifs et réflexion

Les décorateurs natifs permettent d'enregistrer des classes et d'exposer des membres pour y accéder à l'exécution par leur nom.

DécorateurRôle
@registerEnregistre la classe dans la factory.
@exposedExpose un membre à la réflexion. Il doit être public.
@register
class A {
public:
    @exposed int health;
};

Créer des instances

// Instancier par nom
A* obj = stde::factory_new("A");
// transformé par cxxe en : new A()

// Récupérer le type par nom
A* obj2 = new stde::factory_find("A")();
// transformé par cxxe en : new A()

Accéder aux membres exposés

obj->get_member("health") = 4;
// transformé par cxxe en : obj->health = 4;

Usage dynamique

Tout est résolu à l'exécution : le nom peut venir d'une source inconnue à la compilation.

stde::factory_new(unknown_string);
Un membre @exposed doit obligatoirement être public.

Décorateurs custom

Vous pouvez déclarer vos propres décorateurs. Un décorateur reçoit la fonction décorée (func) et l'enveloppe comme vous le souhaitez.

void @my_decorator() -> func(int a) {
    before();
    func(a);
    after();
}

Un décorateur peut aussi prendre des paramètres :

void @my_decorator(/* paramètres du décorateur */) -> func(int a) {
    before();
    func(a);
    after();
}

Utilisation :

@my_decorator
void work(int a) { /* ... */ }
Le support des templates sur les décorateurs est prévu pour une prochaine version.

Décorateurs de cycle de vie

Trois décorateurs standards documentent l'évolution de votre API.

DécorateurDescription
@deprecated(msg)Marque un élément comme obsolète, avec un message.
@since(version)Indique la version où l'élément a été introduit.
@experimental(msg)Signale une API instable, susceptible de changer.
@since("1.2")
@deprecated("Use load_v2() instead")
void load();

@experimental("The interface may change")
void new_feature();

Signals

Un signal détecte les modifications d'une variable et exécute un bloc de code à chaque changement. Il fonctionne partout : portée globale, classes, structures, etc.

int my_int = 0;

signal: my_int {
    var_changed();
}

Dans une classe :

class Player {
public:
    int score = 0;

    signal: score {
        update_ui();
    }
};

defer

defer exécute un bloc à la sortie de la portée courante, quel que soit le chemin de sortie.

void process() {
    FILE* f = fopen("data.txt", "r");
    defer { fclose(f); }

    // ... utiliser f ...
}   // fclose(f) est appelé ici

Enums introspectables

Les enums sont introspectables : conversion enum → string, conversion string → enum et autres opérations de réflexion.

enum class Color { Red, Green, Blue };

Les fonctions d'introspection couvrent notamment :

  • la conversion enum → string ;
  • la conversion string → enum ;
  • d'autres utilitaires de réflexion sur les valeurs de l'enum.

Properties (getters/setters natifs)

Les classes et structures supportent nativement les properties avec get et set, sans boilerplate.

class Character {
    int health;

public:
    property Health {
        get { return health; }
        set { health = clamp(value, 0, 100); }
    }
};

Utilisation :

Character c;
c.Health = 150;    // appelle le setter : health = 100
int h = c.Health;  // appelle le getter

Redirection des sorties (IOutput)

Toutes les sorties peuvent être redirigées nativement, quel que soit le mécanisme utilisé dans le code :

  • std::cout
  • printf
  • std::print
  • et d'autres sorties standards

La redirection repose sur l'interface IOutput : implémentez-la pour envoyer les sorties vers un fichier, une console d'éditeur, le réseau, un log, etc.

Toolchain CMake

C++Extended s'intègre à CMake via une toolchain dédiée. Les sources étendues sont traitées par cxxe avant la compilation C++ habituelle : le langage peut donc être adopté dans un projet existant sans changer le système de build.

Concepts (feuille de route)

Ces éléments sont des concepts à l'étude. Leur syntaxe et leur comportement ne sont pas définitifs, et ils ne sont pas encore implémentés.

Type dynamic

Un type dont le type réel n'est connu qu'à l'exécution, comme en Python. Il permet par exemple de stocker des valeurs de types différents dans un seul conteneur.

std::vector<dynamic> items = { 42, "hello", 3.14 };

Pattern matching

Une instruction match traite une valeur selon son type. Dans chaque branche, la valeur est déjà convertie vers le type correspondant.

match value {
    int: printf("%d\n", value);  // value est déjà un int ici
}

JSON, XML et autres formats de données

Des contrôles natifs pour manipuler les formats de données courants (JSON, XML, etc.) directement depuis le langage.

Sérialisation automatique

Le décorateur @serializable générera automatiquement la sérialisation et la désérialisation d'une classe.

@serializable
class Config {
public:
    int width;
    int height;
};

Notes et limites

  • Les exemples de cette documentation illustrent la syntaxe ; les noms exacts des fonctions de la bibliothèque stde peuvent varier selon les versions.
  • Un membre @exposed doit être public.
  • Les fonctionnalités marquées « Concept » ne sont pas encore implémentées.
